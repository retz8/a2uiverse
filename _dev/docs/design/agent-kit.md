# agent-kit

A kit for building A2UI+A2A agents: `a2uiverse-apps/agent-kit/`, distribution **`a2ui-agent-kit`**, import **`a2ui_agent_kit`**. Protocol-plain — an agent built on it speaks A2UI and A2A and nothing else; `paintMeta` is the one optional, degradable shell convention (a 3.4 scaffold opt-in: "ready for the a2uiverse ecosystem"). Unofficial, downstream of google/a2ui. A uv package (`package = true`, src layout, `uv_build`); the three agents take it as an editable path dependency. Vendor-agnostic by contract: shared logic only — fixtures, prose, tool policy, and cards live in each app's `app/` package and reach the kit through its config.

## Components

- **`config.AgentAppConfig`** — the whole per-vendor surface, one frozen dataclass (identity + skills, `default_port`, `responder_app_name`, `adk_agent_name`, `app_dir` anchoring `.env` and debug dumps, `catalog_path` + `catalog_kind: "custom"|"basic"`, examples/knowledge paths, prompt prose fields, the deterministic response pair, `question_policy`, `stub_tools`, `live_toolset_factory`, `after_tool`, `model`). `eq=False`: a config instance IS the app; identity hashing backs per-config caching. Kit-level `DEFAULT_MODEL`.
- **`catalog.CatalogContext`** (via cached `catalog_context(config)`) — locate/load/validate against the app's catalog: schema managers (default + examples-wired live), `supported_catalog_ids`, `validate_payload` (deterministic partial-update probe), 4-pass `validate_surface` (binding-on-literal pre-pass, conformance, completeness/topology, binding resolvability). `catalog_kind` drives the two branches: `custom` → id-stripped conformance + top-level prop schemas; `basic` → id-retained + `allOf`-flattened props. Schema manager pins `VERSION_0_9` (flip to 0.9.1 is a tracked follow-up).
- **`versions`** — the single `WIRE_VERSION = "v0.9"` constant (the message-family wire tag; distinct from the card's v0.9.1 extension URI and the SDK's schema-version constants).
- **`prompt` / `knowledge`** — system-prompt assembly (slot mapping, workflow join with the domain doc last, examples-framing splice) over config prose and knowledge paths.
- **`paint_meta`** — the `<paint-title>`/`<no-surface/>` streaming tag filter and paintMeta DataPart builder, plus the two named question policies the config selects: `require_carries_action` (basic-catalog agents) and `require_root_component(name)` (bidirectional marker↔dialog consistency; github passes `"ConfirmationDialog"`).
- **`executor_llm.LlmAgentExecutor`** — stream-first / validate-at-end / retry; collaborates with `CatalogContext` (validation, parser ref-fields), `config.question_policy`, the recorder, and an `LlmResponder`; debug dumps anchored to `config.app_dir`.
- **`executor_deterministic.DeterministicAgentExecutor`** — canned A2UI per action/text, over the config's `(build_response, build_text_response)` pair.
- **`responses.fixture_responder`** — the standard fixture-playing pair (load, surfaceId stamping, visible fallback, fresh `<prefix>-N` text surfaces) from an app's fixtures dir + action map; low-level helpers exported for hand-rolled pairs (github). `stub_fixture_loader(fixtures_dir, hint=…)` — the cached loader every app's stub tools read their corpus through.
- **`toolset.PolicyMcpTool` / `PolicyMcpToolset`** — the toolset-wrapper base: per-call interception at `McpTool._run_async_impl` (`shape_args` outbound, `shape_result` inbound, `accepted_args()` off the tool's own MCP schema), tools re-classed to `tool_class` after listing. Standard agent anatomy: every agent's live toolset instantiates it — gmail subclasses (`RecordingMcpTool`: scrub), calendar subclasses (`GuardedMcpTool`: pin/suppress + capture), github uses the base with its no-op hooks — deliberately kept no-op by the write tier (task-3.7 decision 1: no confinement; the confirm gate is the brake).
- **`tool_shaping`** — the shaping mechanics: the annotate-hook-driven walker `shape_tool_response(response, tool_name, annotate=…)` (new-dict, never raises), `record_shape(…, app_dir=…)` + `describe` shape dumps behind `TOOL_SHAPE_DUMP`, shared `PROJECTION_NOTE`/`ANNOTATION_KEY`. What notes SAY is the vendor `annotate` hook's.
- **`corpus`** — record-mode payload capture beside the recorder: `recording()`, `capture_payload` (jsonl append under `<record_dir>/payloads/`), `corpus_payload` (structuredContent-preferring decode). Scrub/mask before capture is vendor policy.
- **`google_adc`** — opt-in Google ADC credential block (`quota_project(vendor)`, `access_token(scopes, vendor)`, `mcp_headers`, `MissingGoogleCredentialError`); wired only by Google-backed vendors (gmail, calendar), never standard anatomy. The 3.4 scaffold asks whether a vendor needs it.
- **`testing`** — the executor-injected in-process harness (`run_executor`, `run_executor_text`), shipped in the package so vendor `tests/helpers.py` are thin per-app bindings of it.
- **`responder.AdkLlmResponder`** — ADK Runner wrapper (SSE token stream, per-`contextId` sessions); agent and `app_name` injected.
- **`recorder`** — `NullRecorder`/`SessionRecorder`, armed by `A2UI_RECORD_DIR`; owns `RECORD_DIR_ENV`.
- **`modes`** — `deterministic|stub|live` → executor, behind lazy imports (deterministic never imports ADK). `build_llm_agent(config, mode)` assembles prompt + tools (`stub_tools` / `live_toolset_factory()`) and adapts ADK's after-tool callback to `config.after_tool(tool_name, tool_response)`. `MODEL_NAME` env > `config.model` > `DEFAULT_MODEL`. The old `TOOL_BACKEND` env switch is retired.
- **`server`** — one A2A Starlette app and **one AgentCard for every mode**, advertising the v0.9.1 extension with the context's catalog ids; CORS for localhost + devtunnels.
- **`cli`** — the single entrypoint behind each app's 3-line `__main__` shim: `python -m app --mode deterministic|stub|live [--host --port --base-url]`; dotenv, timestamped logging, and the 300s keep-alive in all modes; `--port` defaults to `config.default_port` (launched runs pass it explicitly).
- **`beats`** — the headless beat-record driver; each app's `scripts/record_beats.py` shim supplies its beats list, agent URL, and directories.

## Flows

- **Serve**: `app/__main__` → `cli.run(CONFIG)` → `server.build_app(config, mode, …)` → `modes.resolve_executor` → executor over the shared card.
- **LLM turn**: executor → responder stream → lenient parser (+ tag filter → paintMeta parts) → at end `CatalogContext.validate_surface` + `config.question_policy` → retry with correction or complete; recorder captures batches.
- **Deterministic turn**: executor → config pair (usually `fixture_responder`) → stamped canned messages.

## App residue

Each agent keeps one uniform `app/` package — `config.py` (the `AgentAppConfig`), `card.py`, `prose.py`, `responses.py`, `mcp.py` (endpoint, scopes/toolset scope, admitted/withheld inventory where the vendor curates one — github serves the full surface, task 3.7 — and vendor bindings of the credential helpers), `tools.py` (stub bodies over the kit loader), `tool_shaping.py` (the vendor `annotate` + policy: gmail's pseudonymizer/scrub, calendar's pins + injected-address masking, github's notes/tallies), toolset-wrapper subclass (gmail/calendar; github on the kit base), `fixtures/{stub,deterministic}`, `knowledge/` — plus `scripts/` and its own tests (policy assertions through the kit hooks; mechanics tests live in the kit suite). The scaffold CLI (below) generates this same package for a new vendor; the platform's `dev:agents` launcher spawns this entrypoint by manifest discovery (task 3.5). The GitHub agent is write-capable (task 3.7): unrestricted endpoint, explicit-`all` toolset header, no confinement — content-bearing writes propose-and-confirm per its domain doc's Acting section.

## Scaffold CLI — `create-a2ui-agent`

The kit's front door: `a2uiverse-apps/create-a2ui-agent/`, a pnpm workspace package (sibling of `agent-kit/`), bin **`create-a2ui-agent`** — the `create-*` idiom. It scaffolds only; launching is the platform's `dev:agents`. TypeScript on `commander` (flags) + `@clack/prompts` (walkthrough). Never a runtime dependency of an app. The workspace root takes it as a devDependency so pnpm links its bin and `pnpm exec create-a2ui-agent` resolves; built publish-ready (bin, `files`, no workspace-only runtime assumptions) so `npx create-a2ui-agent` is a later publish step.

### Components

- **`cli`** — `create-a2ui-agent [dir] [flags]`: flags with the walkthrough as fallback; `--yes` (or non-TTY stdin) takes defaults where they exist and fails on the rest. Resolves the target dir (`./<id>`), the port suggestion, the repo URL default (git origin of the target's parent), the catalog package's repo-relative directory (git toplevel of the parent, else the parent), the kit pin; runs `scaffold`; then the install step (`--install`/`--no-install`, else asked). Ends with the next-steps note.
- **`answers`** — the eight inputs (`id`, `displayName`, `description`, `port`, `catalogKind`, `googleAdc`, `ecosystemReady`, `repoUrl`), their validators (kebab id without the half suffixes, port range, repo URL), and the derivations: `titleCase`, `pythonIdent`, `catalogPackageName`, `normalizeRepoUrl` (ssh/`.git`/slash → bare https), `catalogIdUrl(repoUrl, repoDirectory)` = `<repo>/blob/main/<dir>/catalogs/v0.9.1/catalog.json`.
- **`prompts.walkthrough`** — the guided path: intro note (what gets generated), one clack step per missing input with its default, `note` blocks explaining the two opt-ins before their confirms, `askInstall` at the end. Cancel writes nothing.
- **`kit`** — where the kit lives (`KIT_REPO_URL`, `KIT_SUBDIRECTORY`, `KIT_PACKAGE`), `templatesDir()`, `kitCheckout()`, and `resolveKitPin(override)`: HEAD sha of the checkout the CLI runs from (`--kit-rev` wins), falling back to HEAD's newest ancestor a remote carries when HEAD is unpushed — a pin no one can fetch makes the scaffold uninstallable. Warns when `agent-kit/` is dirty, and on the fallback names what it leaves out (silent when the unpushed commits never touched `agent-kit/`); refuses only when not in a checkout and no override.
- **`ports.suggestPort`** — one above the highest `agent.url` port among sibling `*/manifest.json`, else 11001.
- **`templates`** — `copyTemplateTree(src, dest, tokens)`: literal copy with `__TOKEN__` substitution in contents and file names; unknown token → error; `_gitignore` → `.gitignore` (npm publish safety). Overlays overwrite the tree beneath them.
- **`generate`** — the four files generated in code: `agentPyproject` (kit as `[tool.uv.sources]` git dep, `subdirectory = "agent-kit"`, `rev = <sha>`), `agentConfigPy` (the `AgentAppConfig`; `ecosystemReady` selects `require_carries_action` + `prose.SHELL_DESCRIPTION`, else a no-op policy and no shell block), `agentMcpPy` (ADC variant binds `google_adc` helpers; plain variant reads `VENDOR_TOKEN`; both raise `LiveToolsetNotWiredError` until `MCP_URL` is set), `manifestJson`.
- **`scaffold`** — refuses a non-empty target; composes `templates/agent` + `templates/agent-kind/<kind>` (+ `templates/agent-google-adc` when opted in) into `<dir>/agent/`, writes the four generated files, copies `templates/catalog/<kind>` into `<dir>/<id>-catalog/`; returns the sorted file list and the catalog id.
- **`install`** — `uv sync` in `agent/`; `pnpm install` at the enclosing pnpm workspace root when there is one (the catalog is a member by the `*/*-catalog` glob), else in the catalog package.

### Templates

- **`agent/`** (common): `app/{__main__, card, prose, tools}.py`, stub fixture, `knowledge/<id>-domain.md`, the test suite (card, catalog, conformance, executor, knowledge examples, llm agent/prompt/tools, responses, server — prompt golden authored on first run), `tests/helpers.py` over `a2ui_agent_kit.testing`, `scripts/record_beats.py`, README, `.env.example`, `.python-version`, `.gitignore`. Prose blocks are generic and correct as shipped; role and scope carry TODO markers. `SHELL_DESCRIPTION` (paint-title/question) is defined always and included only under the ecosystem opt-in; the `<no-surface/>` rule stays in the workflow block because it is the executor's contract.
- **`agent-kind/basic|custom/`**: `responses.py` (event map: `greet` for basic, empty for custom), deterministic fixtures, the knowledge example, `brand-guidance.md`. Hello-surface floor: basic paints Card→Column→(h3, caption, primary Button `greet`); custom paints a lone `Text` root.
- **`catalog/basic/`**: the gmail-catalog shape — upstream basic `catalog.json` with the four identity fields tokenized, `catalog.ts` over `basicCatalog`, Provider with a neutral starter `TOKENS`/`TOKENS_DARK` on its own wrapper (`.<id>-catalog`), scoped `theme.css`, parity + provider tests, self-contained `tsconfig`.
- **`catalog/custom/`**: the package shell with one seed component `Text` (schema, plain-HTML view, folder barrel), `catalog.registry.ts` (`COMPONENTS`/`FUNCTIONS`), `catalog.ts`, Provider as a scope element with `data-portal-root`, `functions/README.md`, `catalog.json` declaring `Text` and `$defs.anyComponent`; catalog, parity (schema ↔ registry ↔ zod surface) and provider tests. The seed exists because the kit's unhandled-event fallback emits a `Text`, so every catalog must declare one.
- Template markdown is `.prettierignore`d in the apps repo: Prettier rewrites `__TOKEN__` as bold.

### Flows

- **Scaffold**: `cli` → (`walkthrough` | defaults) → `resolveKitPin` → `scaffold` → optional `install` → next steps.
- **Drift gate** (`test/scaffold-run.test.ts`, in `pnpm verify`): scaffold each kind into a temp dir, rewrite the pin to a path dep on the working-tree `agent-kit/`, `uv sync` + `uv run pytest`, then `pnpm install --ignore-workspace` + typecheck + test in the catalog. Skips with a warning when `uv`/`pnpm` are missing or the CLI is not running from the apps checkout. Snapshot tests pin the file list and the four generated files.
