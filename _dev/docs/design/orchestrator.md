# Orchestrator — system design

`apps/orchestrator`. An A2A agent server (SPEC §10); the only thing the client talks to. State as of task 6.6 (M3s): Registry · Embedder · Router · Planner · Synthesizer · AgentsPool · IntentJournal behind one executor, with Partitions and the IntegrityChecker on the composition. Two model calls per synthesized utterance turn (Planner — the readers as tool steps inside the one call, plus one retry when its document fails validation — then Synthesizer once every source has resolved, plus one retry when its document fails validation); the composition state is canonical here, the shell surfaces its rendered projection.

## Process

```
index.ts ── loadConfig() ── buildOrchestrator({config, overrides?}) ── await init() ── express.listen(PORT)
                                   │                                        │
             ┌───────────┬─────────┼─────────┬──────────────┐     registry.refreshCards
          Registry    Embedder   Router   Planner      AgentsPool   (vendor cards fetched at boot;
             │           │         │      (readers)         │        unreachable ⇒ null card,
             └───────────┴── OrchestratorExecutor ──────────┘        unroutable this session;
                          │              │                           the platform's card in hand)
                    IntentJournal   DefaultRequestHandler(card, InMemoryTaskStore, executor)
                                         │
                    GET /.well-known/agent-card.json · POST / (JSON-RPC)
```

`buildAgentCard(BASE_URL)` is built once and read twice: `DefaultRequestHandler` serves it; the Registry indexes it under `shell`. `platformReaders({registry, canvas, recent})` closes over the Registry, the `compositions` map the executor holds, and the journal's ring, and is handed to the `ModelPlanner` as its readers.

Config (env): `PORT` 10001 · `BASE_URL` (card url) · `STATE_DIR` · `A2UIVERSE_AGENT_URLS` · `A2UIVERSE_AGENTS_DIR` (roster from manifests one level below it, replacing the hardcoded entries; the launcher's variable — the mock tier's opt-in) · `A2UIVERSE_DEBUG_IDS` · `GOOGLE_API_KEY` (Planner and Synthesizer; missing ⇒ boot warning, palette turns are broken turns, syntheses collapse as `failed`) · `A2UIVERSE_PLANNER_MODEL` (default `gemini-2.5-flash`) · `A2UIVERSE_PLANNER_EFFORT` (`low` default — `low` spends no thinking budget; latency is time-to-first-paint) · `A2UIVERSE_SHORTLIST_CAP` (default 5) · `A2UIVERSE_SYNTHESIZER_MODEL` (follows the Planner's) · `A2UIVERSE_SYNTHESIZER_EFFORT` (`low`; dead air is measured before effort is spent).

`buildOrchestrator` takes injection `overrides` — `{embedder?, planner?, synthesisModel?, resolveCard?}` — so tests run with no model download, no model call, no card network.

The synthesis mechanism end to end — the synthesize data model, the wire shapes, the client's
evaluation — is told in [`synthesis.md`](synthesis.md).

Every request that crosses the hub's boundary leaves a line on stdout (`log.ts`, task 5.7): one per inbound request (kind, task, context, bytes), one per plan (`plan task=… planned|malformed N ms`, task 6.6), one per relay start and per relay settle (outcome, ms), one per turn close (outcome, ms). The journal records a turn only when it closes; these lines are the trace of one that does not.

## The turn (M3s)

`classifyTurn(userMessage)` routes each incoming client message: `utterance` (text) · `action` (`data.action` with namespaced surfaceId) · `clientError` (`data.error`, e.g. `VALIDATION_FAILED`) · `unknown` (broken turn).

```
utterance:
   1  bus.publish(synthetic Task{state: working})            always first, stamp {source:'shell', role:'shell'}
   2  turn = journal.open(...)
   3  shortlist = router.shortlist(text)                     ranked, capped, no threshold; the platform's card ranks
                                                              among the vendors'; empty is handed on as is
   4  outcome = planner.plan({utterance, shortlist, conversationId})   the one model call, the readers as steps
        inside it; planMs (from 3 to here) logged and journaled; malformed (both attempts refused) ⇒ broken
        turn, the last attempt's findings on the final
   5  state = compositionFrom(document, registry, text); compositions.set(contextId, state)
   6  bus.publish(shell paint: createSurface shell:main · updateDataModel (only when the literal model is
        non-empty) · updateComponents of the painted tree)   BEFORE any dispatch (§4.5)
   7  per source entry (never `shell`, never a gap): pool.dispatch(source, Planner-authored request + partition-filtered metadata)
        per event: relayEvent → composeFragment → partitions.apply → bus.publish
   8  per handle.done: outcomeToSlotState → flip slot → shell repaint (updateComponents only);
        completed-and-painted ⇒ source arrived; lastSettledAt
   9  synthesis (when the dispatch has a `shell` entry):
        < 2 arrived ⇒ slot collapsed, journal `skipped` (§5.1)
        ◆ synthesizer.synthesize({utterance, request, sources}, partitions) — text out, extract →
          validateSynthesis; one retry with the findings; second failure ⇒ malformed
        declined ⇒ the reason spoken as the shell's words into the synthesis slot, then slot collapsed
        malformed | model failure ⇒ slot collapsed silently; journal names which
        else payload = {dataModel, sorts}; state.synthesis = {document, payload};
             paint shell:synthesis into the synthesis slot — the model's tree verbatim, the payload on metadata
             (nothing else moves)
        state.mergedView = {outcome, reason?} in every case
  10  one turn-final (completed; canceled only when every dispatch cancelled). No source entry and no
        `shell` entry — a platform answer, a gap — ⇒ the final follows first paint directly
  11  journal: plan {outcome, layoutSurface?, attempts, toolCalls, planMs} · dispatch records · surface touches ·
        synthesis {outcome, reason?, synthesizeDataModel?, note?, attempts, changes?, deadAirMs} · close
   finally: bus.finished()

action:   parseSurfaceId(action.surfaceId) → owner.
          owner `shell` (a shell action the client reports after handling it: `openStore` · `openAppLibrary`,
          the shell catalog's SHELL_ACTIONS): journaled from the message and nothing else — no dispatch,
          no paint — then a completed final; any other name ⇒ failed final `unknown shell action: <name>`.
          vendor owner: partitions.applyClientDataModel(returning data model); un-namespace the action
          part; partition-filter metadata; single owner dispatch (no Router/Planner); same pump
          (materialize); then, if a live synthesis exists and checkSynthesisPayload
          against the partitions finds a ref that no longer resolves ⇒ re-synthesis inline (step 9)
          handed the previous document and the change account, before the final. A failed dispatch
          flips the slot failed; an action that paints nothing never collapses it.

clientError: flip that surface's slot to failed on the stored composition → shell repaint → completed final.

cancelTask(taskId) → pool.cancel(taskId) — aborts every handle of the fan-out; all-cancelled ⇒ canceled final.
```

Broken turn (both Planner attempts refused, Planner throwing, missing key, unknown message, unknown shell action): failed final stamped as the shell, journal `failed`. One agent failing never fails a fan-out turn.

## Composition

- **State** (`composition/state.ts`): `CompositionState {layout, utterance, slots, gaps, partitions, arrived, synthesis?, mergedView?, lastSettledAt?}`, held per `clientContextId` in the `compositions` map the executor and the this-canvas reader share — surviving the turn so a later action, `VALIDATION_FAILED` or reader finds it. `layout` is the Planner's accepted `LayoutSurface`; `slots: Map<source, {plan: SlotPlan {source, displayName, request}, state}>` keyed by source in dispatch order (the `shell` entry's display name is `Synthesis`, a vendor's the Registry's); `gaps` the gap strings in dispatch order. `compositionFrom(layout, registry, utterance)` builds it. `synthesis` is the `LiveSynthesis {document, payload}` once painted: the accepted synthesize data model and the payload the client holds, what the IntegrityChecker guards; `mergedView {outcome, reason?}` is what became of the merged view once decided, read by the this-canvas reader. Slot states are `pending | failed | collapsed`; `filled` is the client's. `outcomeToSlotState`: failed/timeout → failed · cancelled → collapsed · completed with zero surface touches → collapsed · completed with touches → left to the client (and the source counts as arrived). `synthesisSlot(state)` is the `shell` slot when the dispatch reserved one.
- **Partitions** (`composition/partitions.ts`): every surface's materialized data model keyed by namespaced id, applied from relayed A2UI ops (`createSurface`, `updateDataModel` at an RFC 6901 path — where `/`, A2UI's default, is the root rather than RFC 6901's empty-string key (task 4.8) — `deleteSurface`) and from the returning client data model. `resolve(ref)` goes through the sdk's resolver (phase decision 23): a value, or absent with its reason (`missing` · `ambiguous` · `null` · `positional`), which the checklist reports by name.
- **IntegrityChecker** (`composition/integrity.ts`): `refValid(ref, partitions)` — does the ref resolve now (task-5.10 decisions 1 and 4); `checkSynthesisPayload(payload, partitions) → {valid, invalid: surfaces}` gates re-synthesis; `changeAccount(payload, partitions) → {absent: refs}` is what the Synthesizer is told broke, each ref once.
- **Synthesis painter** (`composition/synthesisPainter.ts`): `shell:synthesis`, the shell's second surface. `synthesisParts(tree)` is `createSurface` in the shell catalog plus `updateComponents` carrying the model's components verbatim (task-5.4 decision 10); a re-synthesis paints the same surface again. `synthesisEnvelope` stamps `{source: shell, role: fragment}` and carries the payload `{dataModel, sorts}` under the sdk's `SYNTHESIS_KEY` (`a2uiverseSynthesis`); `synthesisProseEnvelope` carries a decline's reason as a text part under the same stamp, no payload.
- **Names** (`composition/constants.ts`): shell surfaces `shell:main` and `shell:synthesis` (reserved `shell` source id, namespaced like every fragment; Registry rejects an app claiming `shell`); slots keyed by source, their component ids the model's; the synthesis slot labelled `Synthesis` (`SYNTHESIS_DISPLAY_NAME`); the painter's wrappers `attribution-<slotId>` (`PAINTER_ID_PREFIX`, `planner/validate.ts`, refused on a model id).
- **Shell painter** (`composition/shellPainter.ts`): pure state → A2UI parts in the shell catalog (`CATALOG_ID` via the `@a2uiverse/shell-catalog/id` subpath, no React). `shellCreateParts(state)`: `createSurface shell:main` · `updateDataModel {value: layout.dataModel}` only when the model is non-empty · `updateComponents` of `paintLayout(state)`; `shellRepaintParts(state)`: the `updateComponents` alone. `paintLayout` keeps the model's components and ids in order and writes in what the shell owns: each vendor `Slot` (a `source` other than `shell`) is preceded by an `Attribution {id: attribution-<slotId>, displayName, appId, child: <slotId>, weight}` (the weight copied when the model wrote one), every `child`/`children` reference to the slot rewired to the wrapper, and the `Slot` itself gains `state` (the composition's, `pending` when unknown) and `label` (the display name); the synthesis slot stays bare with `state`, `label: Synthesis`, `content: 'shell'`; a gap slot is emitted as authored (the catalog draws the tile). A repaint locates each `Slot` by `source`, so every id stays put. Envelope (`shellEnvelope`): non-final `working` status-update whose `status.message.parts` carry single-object `version:'v0.9'` DataParts, stamped `{source:'shell', role:'shell'}`.
- **Fragment relay** (`composition/fragmentRelay.ts`): applied after `relayEvent` — stamp gains `role:'fragment'` beside its `source`; surfaceIds namespaced `<appId>:<surfaceId>` on the four A2UI ops (single-object and `messages[]` forms); **vendor finals demoted** (`final:false`, terminal states → `working`) because several vendors end on one orchestrator task — the executor owns the single turn-final. The demotion is envelope ownership, like the id rewrites — not a content rewrite; the relay-transparency invariant stays: exactly three content-affecting rewrites (stamp · namespace · partition filter).
- **Partition filter** (`composition/partition.ts`): `vendorMetadata(metadata, appId)` — outbound messages carry only A2UI-standard keys; `a2uiClientDataModel.surfaces` filtered to the owner's namespace, keys un-namespaced; nothing a2uiverse-specific rides the vendor wire.

## Id spaces

```
client ──(clientContextId, clientTaskId)──► orchestrator ──(vendorContextId, vendorTaskId)──► app
```

One client conversation maps to one vendor conversation per app. Relayed events carry only the orchestrator's ids; outgoing messages carry only the vendor's. Surfaces add the namespace dimension: vendor-local ids on the vendor wire, `<appId>:`-prefixed toward the client, reversed on inbound actions.

### Router — `router/router.ts`

Retrieval only: embed the query, cosine-rank `registry.routable()`, cap the shortlist. No similarity threshold — the Planner makes the semantic selection from the shortlist. `ShortlistEntry {record, card, score}`; the platform's card is one entry like a vendor's. Empty corpus ⇒ empty shortlist, handed to the Planner as is.

### Planner — `planner/`

The turn's one model call (SPEC decision 9, §5.6): the author of `shell:main` — who answers, the layout tree in the shell catalog, the platform's own answers — text out, validated after, the Synthesizer's loop with the platform readers as tools inside the call. Behind two seams: `Planner {plan({utterance, shortlist, conversationId}) → PlanOutcome}` and `getModel(settings)`.

### OrchestratorExecutor — `executor.ts`

Implements the SDK's `AgentExecutor`. Deps `{registry, pool, journal, router, planner, synthesizer, compositions}` — `compositions: Map<clientContextId, CompositionState>` is handed in by `buildOrchestrator` and shared with the this-canvas reader. Owns the synthetic initial `Task` and **every** turn-final (vendor finals are demoted) — after synthesis, in both utterance and action turns. Turn shapes: `#utteranceTurn` (shortlist → plan → `planMs` log line and journal → first paint → the dispatch pumps → `#synthesize` → final; no dispatch and no synthesis ⇒ the final right after first paint) · `#actionTurn` (owner-only dispatch, the inline re-synthesis) · `#shellActionTurn` (an action whose surface owner is `shell`: the name checked against the shell catalog's `SHELL_ACTIONS`, nothing dispatched, nothing painted — the journal entry `open` wrote from the message is the whole of it; an unknown name throws and fails the turn) · `#clientErrorTurn` · `#pump`. Logs one line per inbound request, per plan, and per turn close (`log.ts`). Collaborators: Registry, Router, Planner, Synthesizer, AgentsPool, IntentJournal, the composition modules.

### AgentCard — `agentCard.ts`

Static, `buildAgentCard(baseUrl)`: name `A2UIVerse Orchestrator`, description, `url = BASE_URL`, protocol 0.3, JSON-RPC, streaming, the A2UI v0.9.1 extension (no params), and hand-authored skills (task 6.4): `palette` beside `platform` (What A2UIVerse is) · `canvas` (What the canvas can do) · `installed-apps` · `find-and-install` (the Store and the App Library), each with tags and example utterances; no union of the installed apps' skills. One card, two readers: the client fetches it; the Registry indexes it under `shell`.
