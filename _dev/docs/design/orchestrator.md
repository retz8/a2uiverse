# Orchestrator — system design

`apps/orchestrator`. An A2A agent server (SPEC §10); the only thing the client talks to. State as of task 8.7 (M6): Registry · Embedder · Router · Planner · Synthesizer · AgentsPool · IntentJournal behind one executor, with Partitions, the IntegrityChecker, the synthesis trigger and the reader's presses on the composition. Two model calls per synthesized utterance turn (Planner — the readers as tool steps inside the one call, plus one retry when its document fails validation — then Synthesizer once the trigger releases it and no source it reads has a press in flight, plus one retry when its document fails validation); the composition state is canonical here, the shell surfaces its rendered projection.

## Process

```
index.ts ── loadConfig() ── buildOrchestrator({config, overrides?}) ── await init() ── express.listen(PORT)
                                   │                                        │
             ┌───────────┬─────────┼─────────┬──────────────┐     registry.refreshCards
          Registry    Embedder   Router   Planner      AgentsPool   (vendor cards fetched at boot;
             │           │         │      (readers)         │        unreachable ⇒ null card,
             └───────────┴── OrchestratorExecutor ──────────┘        unroutable this session;
                          │              │                           the platform's card in hand)
                    IntentJournal   DefaultRequestHandler(card, InMemoryTaskStore, executor)
                                         │
                    GET /.well-known/agent-card.json · POST / (JSON-RPC)
```

`buildAgentCard(BASE_URL)` is built once and read twice: `DefaultRequestHandler` serves it; the Registry indexes it under `shell`. `platformReaders({registry, canvas, recent})` closes over the Registry, the `compositions` map the executor holds, and the journal's ring, and is handed to the `ModelPlanner` as its readers.

Config (env): `PORT` 10001 · `BASE_URL` (card url) · `STATE_DIR` · `A2UIVERSE_AGENT_URLS` · `A2UIVERSE_AGENTS_DIR` (roster from manifests one level below it, replacing the hardcoded entries; the launcher's variable — the mock tier's opt-in) · `A2UIVERSE_DEBUG_IDS` · `GOOGLE_API_KEY` (Planner and Synthesizer; missing ⇒ boot warning, palette turns are broken turns, syntheses collapse as `failed`) · `A2UIVERSE_PLANNER_MODEL` (default `gemini-3.7-flash`, task 7.8) · `A2UIVERSE_PLANNER_EFFORT` (`low` default — `low` spends no thinking budget; latency is time-to-first-paint) · `A2UIVERSE_SHORTLIST_CAP` (default 5) · `A2UIVERSE_SYNTHESIZER_MODEL` (follows `A2UIVERSE_PLANNER_MODEL` when set, else `gemini-3.7-flash`, task 7.13) · `A2UIVERSE_SYNTHESIZER_EFFORT` (`low`; dead air is measured before effort is spent) · `A2UIVERSE_SOFT_DEADLINE_SECONDS` (default 10, task 8.3) · `A2UIVERSE_HARD_CAP_SECONDS` (default 300, task 8.3) · `A2UIVERSE_HEARTBEAT_SECONDS` (default 30, task-8.7 decision 31) · `A2UIVERSE_FAULTS` (the dev-only fault map, JSON keyed by app id; unset is none, malformed fails boot naming the entry, task 8.3). A deadline other than its default and an active fault map are each said once at boot.

`buildOrchestrator` takes injection `overrides` — `{embedder?, planner?, synthesisModel?, resolveCard?}` — so tests run with no model download, no model call, no card network.

The synthesis mechanism end to end — the synthesize data model, the wire shapes, the client's
evaluation — is told in [`synthesis.md`](synthesis.md).

Every request that crosses the hub's boundary leaves a line on stdout (`log.ts`, task 5.7): one per inbound request (kind, task, context, bytes), one per plan (`plan task=… planned|malformed N ms`, task 6.6), one per relay start and per relay settle (outcome, ms), one per hard cap reached, per answer held past it and per vendor cancel sent or refused, one per merge released, collapsed or thrown away, one per superseded turn, one per turn close (outcome, ms). The journal records a turn only when it closes; these lines are the trace of one that does not.

## The turn (M6)

A message whose id was already received (`#received`, the last `RECEIVED_IDS_KEPT = 256`) is refused before anything else: after the synthetic Task, a `failed` final "This request was already received." and the log line `← duplicate message=… — refused`; nothing is dispatched and nothing journaled (task 7.9). Otherwise `classifyTurn(userMessage)` routes each incoming client message: `utterance` (text) · `action` (`data.action` with namespaced surfaceId) · `operation` (the composition contract's `data.operation`, read by the sdk's `readOperation`: Retry · Include · Try again; task 8.4) · `clientError` (`data.error`, e.g. `VALIDATION_FAILED`) · `unknown` (broken turn, a malformed operation among them).

Every request's stream carries a heartbeat (`#heartbeat`, task-8.7 decision 31): each publish resets its clock, and after `heartbeatMs` with nothing sent an empty `working` status-update — no parts, no stamp — goes out, until the stream ends; a proxy's idle timeout (the dev tunnel's is 100 s) never cuts a turn waiting on a slow source or the hard cap.

Broken turn (both Planner attempts refused, Planner throwing, missing key, unknown message, unknown shell action, a refused press): failed final stamped as the shell, journal `failed`. One agent failing never fails a fan-out turn.

## Composition

- **State** (`composition/state.ts`): `CompositionState {layout, utterance, turnId, requestMetadata?, slots, gaps, partitions, arrived, merged, folding, pressWork, callFailed?, retrying, owed?, collapses, mergeDecided, presses, making?, reevaluate?, left?, trigger?, operations, retired, synthesis?, mergedView?, lastSettledAt?}`, held per `clientContextId` in the `compositions` map the executor and the this-canvas reader share — surviving the turn so a later action, `VALIDATION_FAILED` or reader finds it. `layout` is the Planner's accepted `LayoutSurface`; `slots: Map<source, SlotEntry {plan: SlotPlan {source, displayName, request, columns?, join?, columnSources?, noun?}, state, failure?, declined?, collapse?, held?, running?, race?}>` keyed by source in dispatch order (the `shell` entry's display name is `Synthesis`, a vendor's the Registry's; `noun` a vendor slot's entries as the join calls them, "CircleCI runs"; `failure {cause, message?}` a failed vendor slot's; `declined` the decline's reason and `collapse` any other collapse's cause, on the merge slot; `held {events, record}` an answer that arrived past the hard cap; `running` a dispatch past its cap still running, `race` an open Retry race's hand-off for its answer); `gaps` the gap strings in dispatch order. `arrived`: sources whose dispatch completed holding a surface and have not failed since. `merged`: the merge's own source set (task-8.3 decision 11) — the sources the accepted synthesis was built over, or the ones a decline or a merge that couldn't be made was made over, which the walk and any re-synthesis cover; only Include, Retry and Try again add to it, a failure removes a source from it. `turnId` and `requestMetadata`: the planning turn — what a press's journal line links to — and its metadata, which a Retry re-dispatches with. `folding`: sources a call owes or is folding in, out of the late ones meanwhile; `pressWork`: calls a press caused, owed or running; `callFailed {kind: include | update, sources}`: the last such call failed with the landed view kept; `retrying`: on a collapsed merge, the retried sources whose arrival brings it back; `owed: Owed {joining, make, walk, presses: OwedPress {kind, sink, resolve}[]}`: what the next call covers; `collapses`: how many times the merge collapsed, which a merge in the making watches (task 8.4). `trigger {unsettle, settle}`: while the first merge is undecided, a retried source rejoining the pack. `operations: Operation {taskId, controller, journal}` the presses running on it, `retired` aborted once a new utterance replaces it. `Sink {ctx, bus, turn, drains?}`: where a turn's events and journal go. `inSlotOrder(state, appIds)`; `lateSources(state)`: arrived, not in `merged`, not folding, once the merge landed, declined or couldn't be made — none under a home or too-few collapse. `mergeDecided`: the turn's one automatic synthesis released, or the merge collapsed instead. `presses`: the reader's presses in flight (task 8.10). `making`: the merge in the making, one at a time. `reevaluate`: while the utterance turn runs, re-weighs the trigger after a slot fails outside it. `left`: while a merge is made, called when a source it reads is reported undrawable, throwing the call away (task-8.7 decision 25). `compositionFrom(layout, registry, utterance, {turnId, metadata?})` builds it. `synthesis` is the `LiveSynthesis {document, payload, watch, seen}` once painted: the accepted synthesize data model, the payload the client holds, the key sets recorded at accept, and what every surface held at accept — what the IntegrityChecker guards; neither `watch` nor `seen` is journaled; `mergedView {outcome, reason?}` is what became of the merged view once decided, read by the this-canvas reader. Slot states are `pending | failed | collapsed`; `filled` is the client's. `outcomeToSlotState(outcome, holdsSurface)`: failed/timeout → failed · cancelled → collapsed · completed holding no surface → collapsed · completed holding a surface → left to the client (and the source counts as arrived). `synthesisSlot(state)` is the `shell` slot when the dispatch reserved one.
- **Partitions** (`composition/partitions.ts`): every surface's materialized data model keyed by namespaced id, applied from relayed A2UI ops (`createSurface`, `updateDataModel` at an RFC 6901 path — where `/`, A2UI's default, is the root rather than RFC 6901's empty-string key (task 4.8) — `deleteSurface`) and from the returning client data model. One surface per source (SPEC §4.1): a `createSurface` retires every other surface of the same app, as the client's slot does, so refs into a surface the canvas no longer holds stop resolving here too (task 7.9). `resolve(ref)` goes through the sdk's resolver (phase decision 23): a value, or absent with its reason (`missing` · `ambiguous` · `null` · `positional`), which the checklist reports by name. `holdsSurfaceOf(appId)`: what arriving means (task-8.3 decision 5). `view(appIds) → PartitionsView`: the partitions of the given sources only — a surface of any other source is not there, so the Synthesizer's refs into it are refused and the walk does not see it (task-8.3 decision 11). `snapshot(appIds)` and `changedSince(snapshot, appIds) → surfaces`: the given sources' surfaces holding other data than at the snapshot, added and gone ones included — the same data painted again is no change (task-8.10 decision 2).
- **Trigger** (`composition/trigger.ts`, pure; task 8.3): `mergePossible(arrived, home?)` — two arrived, the home source among them under an anchored join; a union join has none (task-8.7 decision 30). `decideTrigger({sources, settled, arrived, home?, justSettled?}) → wait | arm | release (settled | home) | collapse (home | few)`: a home source settled without arriving collapses at once; every source settled releases a possible merge or collapses `few`; sources still out arm the soft deadline over a possible merge. The home source is never on the soft deadline.
- **Presses** (`composition/presses.ts`; task 8.10): the reader's presses in flight on one composition, counted per source — `begin(appId)` · `end(appId)` · `pressing(appIds)` · `onEnd(listener) → unsubscribe` · `quiet(within(), signal?) → PressWait[] {appId, ms}`: resolves once no source of `within()` — read afresh after every press ends — has a press in flight, or on abort, naming each source it waited on and for how long.
- **IntegrityChecker** (`composition/integrity.ts`): `refValid(ref, partitions)` — does the ref resolve now (task-5.10 decisions 1 and 4); `checkSynthesisPayload(payload, partitions) → {valid, invalid: surfaces}`. `watchOf(payload, partitions, previous?) → Watch` at every accept: every `WatchedArray {surface, array, fields}` the payload's refs select into by key, one per field set, plus every array the previous watch held, each with its key set now — empty when the array is not there (task-7.6 decision 14). `seenOf(partitions) → Seen` at every accept: each surface's data model as JSON. `changeAccount(payload, partitions, watch?, seen?) → ChangeAccount {absent, appeared, unheld, repainted}`: the refs that no longer resolve, each once; the elements whose key was not in their watched array at the last accept, each as a ref selecting it by key; the facts under `match` that no longer hold while their refs resolve, `UnheldRelation {path, op, args}`; the surfaces the payload reads nothing from whose data differs from `seen` (task 7.9). `firesResynthesis(changes)` — absent, appeared or repainted; an unheld fact fires nothing (task-7.6 decision 13). `composition/relations.ts` `runFact(formula, partitions)` runs a fact on the shell catalog's own relation function, shared with the Synthesizer's validator.
- **Synthesis painter** (`composition/synthesisPainter.ts`): `shell:synthesis`, the shell's second surface. `synthesisParts(tree)` is `createSurface` in the shell catalog plus `updateComponents` carrying the model's components verbatim (task-5.4 decision 10); a re-synthesis paints the same surface again. `synthesisEnvelope` stamps `{source: shell, role: fragment}` and carries the payload `{dataModel, sorts}` under the sdk's `SYNTHESIS_KEY` (`a2uiverseSynthesis`); a decline sends no envelope — its reason rides only on the collapsed shell `Slot` (task 8.5).
- **Names** (`composition/constants.ts`): shell surfaces `shell:main` and `shell:synthesis` (reserved `shell` source id, namespaced like every fragment; Registry rejects an app claiming `shell`); slots keyed by source, their component ids the model's; the synthesis slot labelled `Synthesis` (`SYNTHESIS_DISPLAY_NAME`); the painter's wrappers `attribution-<slotId>` (`PAINTER_ID_PREFIX`, `planner/validate.ts`, refused on a model id).
- **Shell painter** (`composition/shellPainter.ts`): pure state → A2UI parts in the shell catalog (`CATALOG_ID` via the `@a2uiverse/shell-catalog/id` subpath, no React). `shellCreateParts(state)`: `createSurface shell:main` · `updateDataModel {value: layout.dataModel}` only when the model is non-empty · `updateComponents` of `paintLayout(state)`; `shellRepaintParts(state)`: the `updateComponents` alone. `paintLayout` keeps the model's components and ids in order and writes in what the shell owns: each vendor `Slot` (a `source` other than `shell`) is preceded by an `Attribution {id: attribution-<slotId>, displayName, appId, child: <slotId>, weight}` (the weight copied when the model wrote one), every `child`/`children` reference to the slot rewired to the wrapper, and the `Slot` itself gains `state` (the composition's, `pending` when unknown) and `label` (the display name); the synthesis slot stays bare with `state`, `label: Synthesis`, `content: 'shell'`, and the plan's `columns`, `columnSources` and `join` when it wrote them (tasks 7.15, 8.3) — they reach the client as `Slot` props, the stamp unextended; a gap slot is emitted as authored (the catalog draws the tile). The facts a state carries are the painter's too (task 8.3): a vendor slot's `noun` under a join and its `failure {cause, message?}` once failed; the merge slot's `declined {reason}` or `collapse` cause (`home` with the home source's noun · `few` with the display names that answered and, as `failed`, the ids that did not — what the line's Retry all covers, task-8.7 decision 24 · `unmade`) once collapsed — the shell catalog composes the line. And on the merge slot, what the presses' lines are drawn from (task 8.4): `merged` once a view landed, `late` (lateSources), `working {sources}` while `pressWork` — the folding sources that arrived — `callFailed` with a landed view, `retrying` on a collapsed merge; all in slot order. A repaint locates each `Slot` by `source`, so every id stays put. Envelope (`shellEnvelope`): non-final `working` status-update whose `status.message.parts` carry single-object `version:'v0.9'` DataParts, stamped `{source:'shell', role:'shell'}`.
- **Fragment relay** (`composition/fragmentRelay.ts`): applied after `relayEvent` — stamp gains `role:'fragment'` beside its `source`; surfaceIds namespaced `<appId>:<surfaceId>` on the four A2UI ops (single-object and `messages[]` forms); **vendor finals demoted** (`final:false`, terminal states → `working`) because several vendors end on one orchestrator task — the executor owns the single turn-final. The demotion is envelope ownership, like the id rewrites — not a content rewrite; the relay-transparency invariant stays: exactly three content-affecting rewrites (stamp · namespace · partition filter). `withoutFailureWords(event)`: a vendor's failed final loses its words, which ride only on the `Slot`'s `failure` (task-8.3 decision 6); data parts stay. `retask(event, taskId)`: a held answer drawn by a Retry moved onto its task, parts and stamp untouched (task 8.4).
- **Partition filter** (`composition/partition.ts`): `vendorMetadata(metadata, appId)` — outbound messages carry only A2UI-standard keys; `a2uiClientDataModel.surfaces` filtered to the owner's namespace, keys un-namespaced; nothing a2uiverse-specific rides the vendor wire.

## Id spaces

```
client ──(clientContextId, clientTaskId)──► orchestrator ──(vendorContextId, vendorTaskId)──► app
```

One client conversation maps to one vendor conversation per app. Relayed events carry only the orchestrator's ids; outgoing messages carry only the vendor's. Surfaces add the namespace dimension: vendor-local ids on the vendor wire, `<appId>:`-prefixed toward the client, reversed on inbound actions.

## Components

### Registry — `registry/`

Installed apps plus, since Phase 2, the agent-authored mirror: nullable AgentCards fetched at boot and their corpus vectors (SPEC decisions 10/11) — and, since Phase 6, the platform's own card under the reserved `shell` id. Hardcoded module until M7.
