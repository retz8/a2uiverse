# Phase 4 — Synthesis, identical shapes

Spec for Phase 4 (`_dev/TODO.md`), milestone **M2** (SPEC §12): synthesis over two sibling mock vendors — Synthesizer, derived bindings, BindingEvaluator, IntegrityChecker, generation stamps, disclosure.

## Scope

- Two mock vendor agents in `a2uiverse-apps`, scaffolded with `create-a2ui-agent`, serving an identical product shape and quarantined from the default roster.
- The Synthesizer as the turn's second model call, the IntegrityChecker and generation stamps on the orchestrator, the BindingEvaluator on the client.
- The cross-partition qualified ref, its operator vocabulary, and the derived data model they compose into.
- The synthesis surface: reserved at plan time, painted into its slot, sortable, disclosing its own partial values.
- The spec doc edits the above entail (SPEC §5.4, §6.2–§6.3, §14).

The join itself is trivial in this phase. Shapes are identical by construction, so entity resolution is true for free and every remaining hard thing is machinery. Heterogeneous shapes are M3; real entity resolution is M4.

## Locked decisions

### 1. Substrate: two scaffolded mock vendor agents

Two mock vendors, generated by `create-a2ui-agent`, running as real A2A agents on the real wire — their own ports, catalog packages, manifests, and AgentCards. Not orchestrator-side fixtures, and not two of the existing three agents. Synthesis is exercised against real partitions, real namespacing, real fan-out, and real unsynchronized arrival; the phase doubles as the first non-authored use of the Phase 3 kit.

### 2. Domain: two storefronts over a shared product shape

The mocks are storefronts serving the same products under matching ids, differing on values. The join is entity-based and true by construction. This is the shape of SPEC §3's S2 — the declared architectural target — and of §5.2's own worked example. It makes M4 the same substrate made harder rather than a fresh one.

"Sibling" means only that the two mocks are authored as a matched pair so their data shapes are identical. Similar domain does not imply identical shape; that disagreement is M3's problem.

### 3. The cross-partition ref is the phase's protocol delta

A2UI v0.9.1 binds by JSON Pointer only — no expressions, no computed values — and paths are surface-scoped, so cross-partition reference is unrepresentable. The delta is taken at exactly that point: a provenance-qualified ref. Operators are declared as A2UI catalog `FunctionDefinition`s in the shell catalog, so the vocabulary stays catalog-declared and validator-visible.

### 4. The derived data model is a list of resolved entities

Each entry is one resolved entity; its cells are refs or formulas over refs. Entity resolution *is* entry membership — placing two vendors' paths in one entry is the assertion that they are the same thing. Rendering is a separate output (§5.2 item 2), so the model is entity-shaped without committing the UI to a table. The named sort criterion orders the list.

### 5. Index-based refs, generation stamps as the floor

Refs address by index in this phase; generation stamps are the correctness floor. Key-based refs arrive in Phase 5. With keys, invalidation is rare and the floor beneath them would ship unexercised; index refs make invalidation the common case, which is when re-synthesis, the IntegrityChecker's gate, and tier-2 invalidation are found to work. Both kinds are permanent — Phase 5 adds a variant beside this one and deletes nothing.

The accepted cost: this phase re-synthesizes more often than the finished system will.

### 6. Absent is not invalid

Two distinct states, which the spec implies but does not name:

- **Absent** — the ref's path no longer resolves. Free and reversible. Formulas recompute over what still resolves; no model call.
- **Invalid** — the path still resolves but may now point at a different entity. The only genuine correctness hazard, and what generation stamps exist to catch.

A partition's generation bumps only when a ref could be silently re-pointed — an array a live ref indexes into is mutated in place. Conflating disappearance with re-pointing is what would make §6.3's "degrade locally and free" unimplementable.

The absent round trip is proven in this phase: the mocks carry a drill-down so refs go absent and resolve again.

### 7. The synthesis fragment is its own surface

The orchestrator creates it against the shell catalog and it claims the reserved slot, structurally identical to a vendor fragment. Its data model is the derived model. Painting it touches nothing else, which is §5's "nothing else moves" for free. It is client-held (§11) while the composition that produced it stays orchestrator-canonical: the orchestrator emits the wiring once, the client owns evaluating it until a tier-2 invalidation.

### 8. Planner: the reservation lands, the judgment stays easy

The plan schema gains the synthesis reservation and the prompt learns to use it. The slot must exist at first paint (§5 t3), before dispatch, so the mechanism cannot wait. The judgment is thin here because two sibling storefronts always merge; it matures in Phase 5 against a heterogeneous roster, which is a prompt change and not a structural one. Capability gaps stay out entirely.

The Synthesizer's decline (§5.1) is exercised deliberately, via a question whose results do not overlap: the reserved slot collapses and the fragments stand side by side.

### 9. Evaluate, then render

The wiring rides A2A metadata, as placement already does (§4.1). The A2UI surface the orchestrator paints is standard. Client-side, the BindingEvaluator resolves refs against the partitions it holds, computes the formulas, and produces an ordinary data model; the renderer sees plain values and plain paths. No renderer fork, no component fork, vendor catalogs unaffected. Operators are declared in the catalog and executed in the evaluator.

### 10. Sort only

The sort criterion is displayed and user-changeable (§5.2), and a sort change is a re-order in the evaluator — no model call, no round trip. Navigation from a shell-painted cell to the originating vendor subtree, and the per-partition reverse index it requires (§7), is an explicit Phase 5 carry. In this phase the merged surface is read-only except for sort.

### 11. Mock backing and quarantine

The mocks support all three run modes, with `live` meaning an LLM over an in-repo dataset — there is no MCP behind an invented store. `deterministic` and `stub` remain the substrate for tests and recorded beats.

The mocks are **quarantined**: a separate tier in `a2uiverse-apps`, excluded from default launcher discovery and from the default registry, opted in explicitly. The Router does retrieval over the AgentCards in the roster, and two fictional storefronts resident in that corpus would be noise in every later phase. They are kept permanently, not deleted — the only substrate where the join is guaranteed correct, and therefore the clean-room regression bed for the Synthesizer.

### 12. Formulas are flat, and skip absent inputs

One cell is one operator over N refs. No nesting: a recursive grammar is not expressible as structured output, the same constraint that already unrolls the plan's layout tree. Aggregates skip absent inputs and carry their contributor count, which makes decision 6's degradation fall out of the evaluator rather than needing special handling, and supplies the source set §5.2 requires derived values to disclose.

### 13. IntegrityChecker: per-binding interface, generation-backed

Orchestrator-side, running on repaint, gating whether the Synthesizer runs. The orchestrator materializes partitions — which the Synthesizer's input (all partitions, names and values) requires regardless — from relay traffic and the client data model that already returns to it.

Under index-only refs, per-binding validity collapses to per-partition validity: two refs into one partition can never disagree. The interface is per-binding as §6.2 specifies; the implementation currently answers from the partition's generation. Phase 5 adds key resolution as a second answer path behind the same interface. This is deliberate and the spec says so.

### 14. No injected disclosure line

§5.4's requirement survives; its form does not. Absence renders in the cell, the criterion is carried by the sort control, and provenance is already answered by the shell-drawn `Attribution` the synthesis surface receives as a fragment in a slot. A caption stating what a control already shows is redundant, and a summary line is worse-located than the cell where the difference actually is. Amends §5.4 to state the requirement rather than the form.

### 15. Re-synthesis is exercised on purpose

The mocks carry a second instrument: an in-fragment control that mutates their own list in place. Paired with decision 6's drill-down, the two paths are each provoked deliberately — **drill-down → absent → free**, **in-place reorder → invalid → re-synthesize**. Without it the tier-2 gate would ship unexercised, for the same reason key-refs-first was rejected.

### 16. Dead air: out of scope, measured

The interval between the last fragment and the synthesis paint stays unmitigated; §16 files streaming the synthesis fragment as available and unspent. Acceptance measures the interval on the real path, so spending the mitigation later is decided on evidence.

### 17. Partial values disclose through a shell-owned component

A derived cell whose inputs were partial must not render identically to one whose inputs were complete. Because the synthesis tree is model-authored, the guarantee cannot live in the tree: the Synthesizer binds formula cells to a shell-owned component, enforceable as a review rule, which renders value together with contributor state. The `Attribution` pattern applied to values rather than fragments. Partial, absent, failed, declined and not-yet-arrived are one visual problem; the vocabulary is built here, where every state can be produced on demand.

### 18. Acceptance roster: the profile replaces

Under the synthesis profile the roster is the two mocks alone, so a failed acceptance run points at synthesis rather than routing. A mixed-roster run is available as an extra, not a gate.

## Invariants

- **A2UI content stays standard; composition rides the envelope.** The delta is a pre-render evaluation layer A2UI never sees. An existing A2UI agent still composes with zero changes.
- **The Synthesizer emits wiring, never values.** No merged data object exists anywhere; the synthesis surface is a live query over partitions that stay isolated.
- **The model names things; the runtime counts them.** The Synthesizer picks the sort criterion's name; every count, contributor set and absence is computed.
- **Nothing built here is scaffolding.** Index refs, the absent/invalid split, and the per-binding interface are all permanent; Phase 5 is additive. The mocks are the only disposable thing, and they are kept anyway.
