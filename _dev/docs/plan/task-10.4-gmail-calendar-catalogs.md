# Task 10.4 — Gmail and Calendar catalogs

The Gmail and Google Calendar catalogs each become their own component vocabulary in Material 3's design language, as GitHub's is Primer, and both agents are repainted in them. `[apps]` sub-task: code in `../a2uiverse-apps/gmail/` and `../a2uiverse-apps/calendar/`, worked on that repo's `main`; this plan and the reference notes on this repo's `main`.

## Decisions

1. **Two catalogs.** `gmail/gmail-catalog` and `calendar/calendar-catalog`, one per app folder. Package names and catalog ids unchanged. No code shared between them.
2. **Design-system level.** General Material 3 building blocks, named by what they are, each catalog tuned to its product. Notes in `_dev/references/{gmail,calendar,material3}/README.md`, screenshots untracked.
3. **Hand-built React components on Material 3's published values** — the type scale, shape scale, elevation, state layers and component specs as m3.material.io publishes them today (the 34.0.21 token set). `@material/web` is not used: in maintenance mode since 2024-06 and without card, navigation or search components (`_dev/references/material3/README.md` §1).
4. **Palette generated by Material 3's published method.** `@material/material-color-utilities` 0.4.0, TonalSpot's role-to-tone mapping, over tonal palettes from Google Ecosystem Blue `#4285F4` ([Firebase Brand Guidelines](https://firebase.google.com/brand-guidelines)): primary at the seed's own chroma, as Fidelity keeps it; secondary, tertiary, neutral and neutral variant at TonalSpot's chromas. Light and dark. Nothing sampled from screenshots.
5. **Calendar event colours from the Calendar API's published palette** — the 11 event colours `colors.get` returns, named by Apps Script's `EventColor` ids (Lavender … Tomato), placed in Material 3 tones through HCT for fills that carry white text.
6. **No product icons means the app icon only.** System glyphs are Material Symbols Outlined (Apache-2.0), the 24 px SVGs from `google/material-design-icons`, embedded as path data for the glyphs the catalog offers.
7. **Google Sans ships with each bundle.** Google Sans under the SIL Open Font License 1.1, the latin and latin-ext `opsz` variable files from `@fontsource-variable/google-sans` 5.3.1 with its `OFL.txt`, declared under a family name the catalog owns and applied only inside the Provider's wrapper; `font-optical-sizing: auto` gives Google Sans Text at small sizes.
8. **Scope: what each agent's pinned domain paints** — Gmail: a thread list, one thread, a draft proposed then confirmed, labels. Calendar: an agenda, one event with its guests, an event proposed then confirmed, an RSVP.

## Vocabulary

Both catalogs:

| Component | What it is |
|---|---|
| `Surface` | A Material 3 surface: a container tier, a corner shape and padding, holding one child |
| `Card` | An elevated, filled or outlined card holding one child |
| `Stack` | A flex container: direction, gap, align, justify, wrap |
| `Divider` | A hairline, full width or inset |
| `Text` | A run of text in a Material 3 type role, with weight, colour role and line clamp |
| `Icon` | A Material Symbols glyph from the catalog's set, outlined or filled |
| `Button` | A filled, tonal, outlined, text or elevated button: a label, a leading icon, an action |
| `IconButton` | A standard, filled, tonal or outlined icon button; a toggle when `selected` is bound |
| `Chip` | An assist, filter, input or suggestion chip; selectable |
| `Avatar` | A person's initial in a coloured circle |
| `List` | A list of rows, with optional dividers |
| `ListItem` | One row: leading, headline, supporting, meta and trailing slots; the whole row its action |
| `TextField` | An outlined, filled or plain underlined field with a label; two-way value; multi-line |
| `Checkbox` | A two-way checkbox with a label |

Gmail adds `Tag` (a label's name in a small tinted tag) and `NavigationItem` (a navigation row: icon, label, count, the active pill). Calendar adds `ColorSwatch` (an event colour as a rounded square or dot), an RSVP `status` on `Avatar`, and a large `TextField` size for a title.

The basic catalog's functions stay, from `@a2ui/react`'s implementation; its components go. `Text` keeps a required `text`, which the agent kit's unhandled-event fallback paints.

## Steps

1. **Reference notes** — Gmail, Calendar and Material 3 notes with sources; the colours Google publishes; the Calendar API event palette.
2. **Tokens** — a generator from the seed to light and dark role tokens, the type scale, shape, elevation and state layers as CSS custom properties in a generated sheet scoped to the wrapper class and its dark appearance, prefixed per catalog (`--gm-*`, `--gc-*`).
3. **Font and icons** — the Google Sans files copied to `dist` by the build; the icon path data generated from the upstream SVGs.
4. **Components** — one folder per component: zod schema, view, test. `catalogs/v0.9.1/catalog.json` hand-written with top-level properties; a zod ↔ JSON parity test; the runtime catalog. Class names prefixed `gm-` / `gc-`; every `var()` read names a token the catalog's own sheet defines.
5. **Provider and sheet** — the wrapper carries the catalog class, the appearance and the font family; the sheets scoped to the wrapper class.
6. **Agents** — `catalog_kind="custom"`; `brand-guidance.md` rewritten for the vocabulary; the knowledge examples rewritten; the prompt prose that names basic components updated.
7. **Recording** — the beats re-recorded in `stub` mode; the deterministic fixtures derived from them; the stub fixtures untouched; `test_corpus_is_publishable` green.
8. **Visual check** — the fixtures rendered inside the Provider on a scratch page, screenshotted light and dark, compared with the references.
9. **Live check** — the two catalogs linked into the client, the Gmail and Calendar agents in deterministic mode behind the orchestrator, driven through the tunnel: both fragments render in their catalogs, a merge lands, and a merged value navigates to its element in each fragment.
10. **Docs** — each catalog's README, each agent's README, and the apps root README's rows for Gmail and Calendar.
11. **Gates** — each catalog's build, typecheck and test; eslint and prettier over the Gmail and Calendar paths; `uv run pytest` in both agents.
